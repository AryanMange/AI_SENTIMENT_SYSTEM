Why venv instead of global install?
Without venv — problems

PyTorch 2.0 for Project A breaks PyTorch 1.9 needed by Project B. 2 GB downloaded to system Python. No way to undo. Examiner gets different results on their machine. Versions clash silently.
With venv — clean and safe

Each project lives in its own box. Exact versions locked in requirements.txt. Anyone can reproduce with pip install -r requirements.txt. Easy to delete the venv folder and start fresh.
Golden rule: One project = one venv. Always activate before running any script.

Transformers and Torch — the "brain" of your project
1
PyTorch = the engine
Imagine the AI as a car. PyTorch is the engine. It does all the actual math — multiplying millions of numbers called tensors, handling GPU/CPU routing, and learning from data. Without PyTorch, model weights are just a dead file with no way to run them.
2
Transformers = the steering wheel
HuggingFace Transformers is what lets you control PyTorch in one line. Instead of 10,000 lines of math, you write pipeline("sentiment-analysis", model="cardiffnlp/...") and Transformers handles downloading, loading, tokenizing, running, and returning results.
3
Together = why both must be installed
Transformers calls PyTorch. PyTorch runs on your hardware. The model weights (500 million numbers encoding language understanding) are PyTorch tensors. Remove either one and the other breaks completely.

Troubleshooting — 3 common errors
ModuleNotFoundError
No module named 'transformers'
▼
Why: Venv is not active. You installed in a different Python than what's running.
1-line fix:
source venv/bin/activate # Mac/Linux — then rerun your script venv\Scripts\activate # Windows
Check: terminal must show (venv) before your folder path. If not, this is the fix.
FileNotFoundError
No such file — data/comments.csv or analyzed.csv
▼
Why: Scripts run out of order, or terminal is in wrong folder.
1-line fix:
python data_gen.py && python processor.py && streamlit run app.py # Also check you are inside the sentiment_gov folder: pwd
RuntimeError / OOM
Out of memory — model crashes
▼
Why: BART model (1.6 GB) needs more RAM than available at current batch size.
1-line fix:
# In processor.py, line 1 — reduce BATCH_SIZE BATCH_SIZE = 4 # change from 16 to 4 (or even 1 as last resort)
BATCH_SIZE=1 always works on any machine with 4 GB RAM. Very slow but reliable.

Model deep-dive — tokenization and softmax

What happens inside RoBERTa
1
Tokenization — words become IDs
Sentence split into tokens. [CLS] added at start, [SEP] at end. Each token looked up in 50,265-word vocabulary → integer ID.
2
Embedding — IDs become vectors
Each ID → 768-number vector. "hospital" → [0.21, -0.87, 0.44, ...]. Similar words have similar vectors. "doctor" and "nurse" are close. "road" and "vaccine" are far apart.
3
12 Transformer layers — attention
Every word looks at every other word and updates its meaning based on context. "no doctors" reinforces the negative signal from "hospital". RoBERTa reads BOTH directions simultaneously.
4
Classification head — 3 scores
[CLS] token's 768-number vector → linear layer → 3 raw scores (logits) for NEGATIVE, NEUTRAL, POSITIVE.
5
Softmax — scores become percentages
e^score / sum(e^all scores) for each class. Result: 3 probabilities that sum to 100%. Highest wins.
Softmax live demo — type a sentence
Keyword simulation. Real RoBERTa uses 12 transformer layers for true context understanding.

Zero-Shot — how it knows Healthcare vs Transport
The model: facebook/bart-large-mnli
1
MNLI = Natural Language Inference
BART was trained on 400,000+ sentence pairs to answer: "Does sentence A entail sentence B?" It deeply understands language relationships without seeing your specific labels.
2
Labels become hypotheses
Comment: "Hospital has no doctors, patients are dying."
Label "Public Health Services" → hypothesis: "This text is about Public Health Services."
BART scores: does the comment ENTAIL this hypothesis?
3
Scores all labels, picks winner
Public Health Services → 88% ✓ winner
Infrastructure and Transport → 4%
Education and Schools → 2%
Taxation and Finance → 1%
Change departments instantly — zero retraining needed
DEPARTMENT_LABELS = [ "Hospital capacity and ICU beds", # pandemic mode "Vaccine availability and rollout", "Medicine and drug supply", "Quarantine and isolation policy", "Testing and contact tracing", ] # Just change this list. No retraining. Works immediately.
This is why zero-shot is powerful: it adapts to any governance domain in seconds, without 1,000 labeled training examples per category.

5 critical lines of code explained like you're 5
Line 1 — Loading the AI model (processor.py)
pipe = pipeline("sentiment-analysis", model="cardiffnlp/twitter-roberta-base-sentiment", device=DEVICE)
?
pipeline() is HuggingFace's magic one-liner. It downloads the model (first time), loads it into PyTorch, and wraps it so you can call it like a function with text. cardiffnlp/twitter-roberta-base-sentiment is the model name — Cardiff NLP university trained this on 58 million real tweets. device=DEVICE automatically picks GPU (faster) or CPU.
Line 2 — Running the model (processor.py)
preds = pipe(batch)
?
batch is a list of 16 comment strings. Passing all 16 at once is called batch processing — 10x faster than one at a time. Returns: [{"label": "LABEL_0", "score": 0.91}, ...]. LABEL_0 = NEGATIVE (converted via LABEL_MAP dictionary).
Line 3 — Zero-shot classification (processor.py)
pred = pipe(text, candidate_labels=DEPARTMENT_LABELS, multi_label=False)
?
candidate_labels is your list of department names. BART turns each into a hypothesis and scores them all. multi_label=False means pick exactly one winner. pred["labels"][0] is the winning department. pred["scores"][0] is the confidence percentage.
Line 4 — Building the bar chart (app.py)
fig_bar = px.bar(topic_sent, x="topic", y="count", color="sentiment", color_discrete_map=color_map, barmode="group", text_auto=True)
?
px.bar() creates a Plotly bar chart. topic_sent is a DataFrame with columns: topic, sentiment, count. color="sentiment" splits each bar into 3 sub-bars by color. color_discrete_map sets green=POSITIVE, orange=NEUTRAL, red=NEGATIVE. barmode="group" puts bars side by side. text_auto=True prints count numbers on top automatically.
Line 5 — Real-time auto-refresh (app.py)
if auto_refresh: time.sleep(60) st.rerun()
?
auto_refresh is a Streamlit toggle (True/False). When True: time.sleep(60) pauses 60 seconds, then st.rerun() re-executes the entire app.py from the top. This re-reads realtime_feed.csv and updates all charts — creating the appearance of real-time without WebSockets or Kafka.

Real-time monitoring — added now, here's how
Honest answer: Real-time monitoring was NOT in the original code. It has been added now as realtime_collector.py plus a new live feed section in app.py.
What was added
FileWhat was added
realtime_collector.pyNew script — collects Reddit posts every 30 min, runs each through sentiment model, saves to data/realtime_feed.csv
app.pyNew "Real-Time Live Feed" section — reads realtime_feed.csv, shows last 20 posts, auto-refreshes every 60s, displays live stats
requirements.txtAdded praw (Reddit API) and schedule (job scheduler)
How it works — step by step
1
realtime_collector.py runs in background terminal
You run python realtime_collector.py --simulate in a second terminal. It runs continuously and never exits until you press Ctrl+C.
2
schedule library fires collection every 30 minutes
The schedule library wakes up the script every 30 minutes and calls collection_job(). Like an alarm clock that runs your code on a timer.
3
Posts fetched from Reddit (or simulated)
Real mode: PRAW connects to Reddit, fetches governance posts from r/india, r/politics etc. Simulation mode: picks random realistic posts from the pre-written list — no API key needed.
4
Each post classified by RoBERTa
Same cardiffnlp model classifies each new post → NEGATIVE/NEUTRAL/POSITIVE + urgency score. Results saved with timestamp.
5
Results appended to data/realtime_feed.csv
New rows added continuously. File rotates — keeps only newest 2,000 rows so it doesn't grow forever.
6
Dashboard auto-refreshes every 60 seconds
time.sleep(60) → st.rerun() re-executes app.py, re-reads the CSV, updates all live feed charts. Appears real-time to the user.

What to say to professor
"My system implements near-real-time monitoring using a scheduled Python collector running every 30 minutes. It fetches live Reddit posts via the PRAW API, classifies each using the pre-loaded RoBERTa model, and appends results to a rolling CSV file. The Streamlit dashboard reads this file and auto-refreshes every 60 seconds using st.rerun(). This is a Level 1 real-time architecture — suitable for governance monitoring where minutes-old data is acceptable.
